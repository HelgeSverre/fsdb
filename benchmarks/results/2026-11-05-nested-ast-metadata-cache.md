# Nested scalar AST metadata cache

Filtered source-free scalar subqueries under one additional outer SELECT now reuse successful projection metadata and binding validation within one statement when their projection and predicate contain only literals, qualified columns, and binary operators. The query still evaluates its predicate and projection for each row. An AST node has fixed qualified bindings during a statement, including when a dependent source recreates its row contexts; other expression shapes retain ordinary per-row validation.

The [two-scope benchmark control](2026-11-05-nested-scalar-two-scope-control.md) measures an inner `orders` reference and an ancestor `users` reference. Its [candidate ShortRun](2026-11-05-nested-ast-cache-trial-raw.md) measured 5.68 ms for fsdb and 0.317 ms for MySQL. A nearby unchanged-code control measured 6.21 ms for fsdb and 0.327 ms for MySQL, but the one-scope control moved in the opposite direction during those short runs. These server timings alone are inconclusive.

The checked in-process [profile workload](../CorrelatedNestedProfile/Program.fs) parses once, seeds 10,000 users and 50,000 orders, warms ten executions, then verifies 100 rows and a count total of 250 on each execution. Two candidate runs completed 4,385 and 4,412 queries in 15 seconds; two unchanged-code runs, interleaved after each candidate, completed 4,034 and 4,011. The candidate handled 8.7% and 10.0% more queries than its following control. Each timed run used a newly built Release binary and a fresh process; build and seed time were outside the timed window. The host was shared, so this is evidence for this query shape rather than a general throughput guarantee.

The focused SELECT-boundary test covers immediate and ancestor references, missing-column errors, and repeated `LATERAL` evaluation. `just check` passed 3,885 tests with zero build warnings before the added `LATERAL` assertion; the focused test passed again after that assertion. The cache remains statement-local and stores only successful metadata. More complex expressions and additional correlation levels remain uncached.
