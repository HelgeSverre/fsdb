# EPSG 3857 projected spatial reference system

A disposable MySQL 8.4.11 oracle confirmed the built-in `WGS 84 /
Pseudo-Mercator` SRS (EPSG 3857) and its exact
`INFORMATION_SCHEMA.ST_SPATIAL_REFERENCE_SYSTEMS` definition. WKT point
construction retains the supplied X/Y coordinates, including large values;
the optional `axis-order=lat-long` constructor option does not swap projected
coordinates. `ST_DISTANCE` uses planar geometry distance, including a
LineString-to-Point result of 3, and `ST_LENGTH` uses planar length with
metres as the SRS unit (a 3-4-5 line measures 5 metres or about 16.404199
feet). `ST_ENVELOPE`, `ST_CONVEXHULL`, `ST_ISVALID`, and `ST_BUFFER` accepted
projected geometries in the sampled native calls.

`ST_DISTANCE_SPHERE` refuses projected POINT and MULTIPOINT arguments with
3705/22S00, including a supplied positive radius. A nonpositive radius takes
precedence and returns 3706/22003. The 3705 message names both geometry
types.

fsdb now registers EPSG 3857 with its MySQL catalog definition and linear
unit, dispatches projected distance and length to Cartesian operations, and
admits projected geometries to its planar operation paths. The spherical
distance refusal and radius precedence match the pinned oracle. The
`geographic-spatial-contracts` case verifies the catalog, construction,
distance, unit conversion, envelope, and refusal behavior. Broader EPSG
coverage and non-point geographic calculations remain open.

All 11 projected-SRS steps passed against pinned MySQL 8.4.11 at
`torture/artifacts/runs/20261010T001922748-57372/contracts`. This was a
disposable native macOS MySQL oracle with the same identifier case mode as
fsdb; the entire 112-case, 16,350-step differential lane passed without a
difference. The pinned Linux-container run of the same cases retained only
its nine known identifier-case differences. `just check` passed all 3,254
tests without build warnings.
