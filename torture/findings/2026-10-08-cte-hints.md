# CTE optimizer-hint instantiation and scope

Status: open. Native behavior is pinned; the resolver does not yet represent
separate hint-bearing instances of a referenced CTE.

## Evidence

`torture/scripts/cte-hints-oracle.py` passes all 32 cases on native MySQL
8.4.11. Each case uses a fresh connection and a reset table. The disposable
native server has a 64 MiB buffer pool and redo capacity.

A direct replay through fsdb's session query handler at `02ffd278` differs in
29 cases. The [baseline report](2026-10-08-cte-hints-baseline.json) records every
SQL script, native output, fsdb output, and comparison result. This comparison
checks returned columns, rows, and SHOW WARNINGS output; it does not establish
wire metadata or physical-plan parity.

```sh
python3 torture/scripts/cte-hints-oracle.py
```

## Confirmed differences

An unused CTE does not contextualize semantic hints in native MySQL. For example:

```sql
WITH c AS (SELECT /*+ SET_VAR(max_points_in_geometry=7) */ 1 AS n)
SELECT @@max_points_in_geometry AS n;
```

Native MySQL returns 65536; fsdb returns 7. Unused BKA, QB_NAME, timeout, and
unknown SET_VAR hints likewise must not emit semantic diagnostics. Syntax
warnings still appear for malformed hints inside an unused definition.

CTE names resolve through lexical scopes. A nested WITH declaration can shadow
an outer definition; the unused outer definition must not affect setting
selection, warning emission, or block numbering. A CTE can also reference a
visible outer CTE through a differently named inner definition.

Each reference can instantiate a separate query block. For example:

```sql
WITH c AS (SELECT /*+ BKA(x) */ 1 AS n)
SELECT a.n,b.n FROM c a JOIN c b ON 1;
```

Native MySQL emits unresolved-name warnings for both `select#2` and `select#3`.
fsdb emits only the first. NO_MERGE controls retain both warnings, so warning
multiplicity cannot be inferred from whether execution materializes the CTE.
Repeated references also repeat timeout and unknown-variable diagnostics, and
can conflict on SET_VAR and QB_NAME declarations within the shared statement.

Numbering follows instantiated references and body subqueries, rather than
WITH declaration order. Unresolved-name traversal can still visit sources
before scalar subqueries. Recursive CTEs need special handling: the audited
second reference uses `select#6` and `select#7`, while the first uses blocks 2
and 3. Sequentially numbering only visible SELECT records would miss native
internal allocations.

SQL preparation emits the warnings for all instances. EXECUTE returns the
rows without repeating those context/resolution warnings.

## Implementation requirements

The resolver currently identifies a block by its SELECT source position and
uses distinct source positions to suppress duplicate visits. That identity is
insufficient when multiple CTE instances originate from the same definition.
The mutation traversal also deduplicates referenced CTE names globally within
a statement, which loses repeated references and cannot model lexical shadowing.

The replacement needs explicit instance identity, scoped CTE lookup, and a
recursion guard distinct from ordinary repeated references. Hint source offsets
must remain available for syntax messages without becoming instance identity.
Context diagnostics, SET_VAR selection, and timeout interpretation must consume
the instantiated hint sequence; changing only unresolved-name emission would
leave statement effects wrong.

The existing passing SELECT and mutation contracts remain required controls.
The native recursive and malformed-unused-hint controls in this fixture also
prevent indiscriminate warning suppression. No runtime changes or known-gap
allowlist entries accompany this evidence.
