## Baseline differences at 02ffd278

An unused CTE does not contextualize semantic hints in native MySQL. For example:

```sql
WITH c AS (SELECT /*+ SET_VAR(max_points_in_geometry=7) */ 1 AS n)
SELECT @@max_points_in_geometry AS n;
```

Native MySQL returns 65536; baseline fsdb returns 7. Unused BKA, QB_NAME, timeout, and
unknown SET_VAR hints likewise must not emit semantic diagnostics. Syntax
warnings still appear for malformed hints inside an unused definition.

CTE names resolve through lexical scopes. A nested WITH declaration can shadow
an outer definition; the unused outer definition must not affect setting
selection, warning emission, or block numbering. A CTE can also reference a
visible outer CTE through a differently named inner definition.

Each reference can instantiate a separate query block. For example:

```sql
WITH c AS (SELECT /*+ BKA(x) */ 1 AS n)
SELECT a.n,b.n FROM c a JOIN c b ON 1;
```

Native MySQL emits unresolved-name warnings for both `select#2` and `select#3`.
Baseline fsdb emits only the first. NO_MERGE controls retain both warnings, so warning
multiplicity cannot be inferred from whether execution materializes the CTE.
Repeated references also repeat timeout and unknown-variable diagnostics, and
can conflict on SET_VAR and QB_NAME declarations within the shared statement.

Numbering follows instantiated references and body subqueries, rather than
WITH declaration order. Unresolved-name traversal can still visit sources
before scalar subqueries. Recursive CTEs need special handling: the audited
second reference uses `select#6` and `select#7`, while the first uses blocks 2
and 3. Sequentially numbering only visible SELECT records would miss native
internal allocations.

SQL preparation emits the warnings for all instances. EXECUTE returns the
rows without repeating those context/resolution warnings.

## Implemented scope model

`OptimizerHintScopes` expands referenced definitions through lexical CTE scopes.
Each reference has its own block number and hint context; a separate recursion
guard prevents recursive self-references from expanding indefinitely. Unused
and shadowed definitions contribute no semantic hint instances. Definition
visibility is captured at the CTE declaration, including earlier definitions
and the recursive definition itself where applicable.

One walk supplies numbering, contextualization, and name-resolution order. It
accounts for native block numbers reserved by recursive references and UNION
post-processing without inventing hint locations for those internal blocks.
UPDATE, DELETE, INSERT, REPLACE, and ordinary SELECT use the same scope model.

`OptimizerHintResolution` retains family conflicts and target lookup. Source
offsets remain available for syntax diagnostics; a separate contextual ordinal
orders each instantiated hint. Timeout and SET_VAR interpretation consume the
same instantiated sequence, so repeated references affect both diagnostics and
statement settings correctly. Ordinary top-level timeout and setting hints
retain their fast path, while inline WITH definitions are resolved explicitly.

## Repeated syntax diagnostics

Repeated CTE references replay syntax diagnostics with the CTE body's text and
line numbers. The original warning retains the original statement text,
including executable comments; reparsing uses the expanded CTE body. Recursive
self-references do not replay these warnings. Nested definitions preserve their
lexical scope and warning order relative to semantic hint conflicts.

SQL and binary preparation emit these warnings once, without repeating them on
execution. Hint identifiers follow the session's ANSI_QUOTES mode. The maintained
`torture/scripts/cte-hint-syntax-oracle.py` fixture covers these behaviors against
native MySQL 8.4, alongside root regressions and the `cte-hint-syntax` wire contract.

Validation: `just check` passes 3,105 tests. The maintained syntax/quote-mode
oracle passes 22 native cases. The complete wire lane passes 75 cases and 9,446
steps with zero differences; artifact:
`torture/artifacts/runs/20261008T130229390-38007/contracts`.
